In our team we have something called technical lunches.

It’s a low-key format where someone presents a small topic, pattern, or tool they’ve been working with. Nothing fancy, just sharing knowledge across the team.

I’m fairly new in the team, so this was a good opportunity to both learn something properly and contribute a bit early on.

Topic: MDC (Mapped Diagnostic Context)

The topic I picked was MDC — a simple but very useful feature in logging frameworks like SLF4J.

It lets you attach contextual information to your logs. 

Thread-1
+----------------------+
| MDC                  |
|----------------------|
| saksid = 123         |
| jobbId = abc-xyz     |
+----------------------+

log.info("hello")  --> [saksid=123, jobbId=abc-xyz]

The Problem

MDC is stored per thread. 

Thread-1                     Thread-2
+-----------+               +-----------+
| MDC       |               | MDC       |
|-----------|               |-----------|
| saksid=1  |               |  (empty)  |
+-----------+               +-----------+

log()                      log()
--> has context            --> no context

It does not automatically follow when switching threads.

Cleanup Matters

If you forget to clean up, context can leak: 

Request A sets MDC:

+----------------------+
| saksid = 123         |
+----------------------+

... forgot cleanup ...

Request B:

log.info("oops")

--> still logs with saksid=123

Approaches

I walked through a few different ways of handling MDC:

  • Manual MDC.put() / MDC.remove()
  • MDC.putCloseable() with try-with-resources
  • @Cleanup from Lombok
  • A utility that sets multiple values from a Map
try (MDC scope)
+----------------------+
| saksid = 42          |
| jobbId = def         |
+----------------------+

log()

(scope exits → MDC cleared)

The goal is to make usage safe and predictable without too much boilerplate.

Threads (again)

If you want MDC in another thread, you must copy it: 

Map copy = MDC.getCopy()

Thread-2:
MDC.set(copy)

+----------------------+
| saksid = 42          |
| jobbId = def         |
+----------------------+

Takeaway

  • MDC is thread-local
  • Always clean up
  • Prefer scoped usage
  • Copy context when crossing threads
Good:

[request] → set MDC → log → clear MDC

Bad:

[request] → set MDC → log → (forget) → chaos
